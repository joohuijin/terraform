# Terraform · AWS 인프라 실습

Terraform 수업에서 작성·수정하거나 사용한 AWS 인프라 실습 코드를 정리한 저장소입니다.
EC2와 VPC 구성부터 변수·출력값, 원격 상태, 모듈, 반복문·조건식을 활용한 리소스 관리까지 다룹니다.

## 디렉터리 구성

| 경로 | 주요 내용 |
| --- | --- |
| `02` | EC2·VPC·보안그룹, 변수·출력값, 데이터 소스, ALB·ASG |
| `03` | S3 상태 저장, DB의 원격 상태 참조, 웹·DB 구성 연결 |
| `04` | 공개 모듈 사용, S3 웹사이트 모듈, VPC·EC2 모듈 분리 |
| `05` | 반복문·조건식, IAM 사용자·정책, stage/prod 모듈 재사용, 예약 확장 |
| `minipro1` | Docker 설치용 EC2와 로컬 SSH 설정 생성 |
| `minipro2` | ALB·웹 ASG·DB EC2를 분리한 네트워크 구성 |

번호와 폴더명은 수업에서 사용한 구성을 유지했습니다.
각 실습 디렉터리를 개별적으로 사용하는 자료입니다.

## 주요 실습

- VPC, 퍼블릭·프라이빗 서브넷, Internet Gateway·NAT Gateway와 라우팅 구성
- AMI 데이터 소스와 user_data를 이용한 EC2 초기화
- ALB·대상 그룹·Launch Template·ASG 연결
- 변수와 출력값을 통한 모듈 간 설정 전달
- S3 또는 로컬 상태를 terraform_remote_state로 참조
- count·for_each·for 표현식·조건식을 이용한 리소스 생성 제어
- 공통 모듈을 stage/prod에서 재사용하고 규모·인스턴스 유형을 구분

## minipro1 — Docker 실습용 EC2

VPC, Internet Gateway, 퍼블릭 서브넷, 라우팅 테이블과 EC2를 구성합니다.
user_data.sh에는 Docker 설치·서비스 시작 명령이 있으며,
local-exec와 템플릿으로 실행 PC의 SSH 설정에 접속 정보를 추가합니다.
초기화 스크립트 인코딩과 보안그룹 설정은 실행 전에 보완해야 합니다.

## minipro2 — 웹·DB 계층 분리

| 영역 | 코드에 정의된 구성 |
| --- | --- |
| 네트워크 | 서울 리전 기본값, 가용영역 2개, 퍼블릭·프라이빗 서브넷 각 2개, NAT Gateway 1개 |
| ALB | 퍼블릭 서브넷에 배치, HTTP 80 요청을 웹 대상 그룹으로 전달 |
| 웹 모듈 | 프라이빗 서브넷의 ASG, Apache·PHP 초기화, 최소 2·희망 2·최대 4대 |
| DB 모듈 | 프라이빗 서브넷의 EC2 2대에 MariaDB 설치, 웹 보안그룹의 3306 접근 허용 |
| 출력 | ALB DNS 이름, DB 인스턴스 프라이빗 IP 목록 |

보안그룹은 ALB → 웹 → DB 접근 관계를 참조하도록 구성했습니다.
DB 복제·자동 장애 전환, 애플리케이션의 DB 접속 로직,
부하 지표에 따른 ASG 확장 정책은 포함하지 않았습니다.

05/loop-cond의 확장은 시간표에 따른 예약 작업입니다.
CPU 관련 CloudWatch 경보에는 확장 정책을 실행하는 설정이 연결돼 있지 않습니다.

## 사용 전 확인

실습별로 AWS 리전, AMI, Terraform·Provider·외부 모듈 버전 요구사항이 다릅니다.
기본 VPC, 기존 EC2 키페어, 로컬 공개키 파일, S3 상태 저장 버킷 등을
전제로 하는 코드도 있으므로 선택한 실습의 설정을 먼저 확인해야 합니다.

AWS 인증정보와 DB 비밀번호는 저장소 밖에서 전달합니다.
정리 과정에서 DB 사용자명·비밀번호 기본값을 제거하고,
03의 DB 비밀번호를 기존 입력 변수에 연결했습니다.
minipro1의 로컬 인증 파일 경로·프로필 지정도 제거했습니다.

sensitive는 표시를 제한하는 설정이며, 상태 파일에 비밀번호가
저장되지 않는다는 뜻은 아닙니다.
상태 파일, 개인키, 실제 변수 값 파일과 .terraform 작업 디렉터리는 공개 대상에서 제외했습니다.
